# ♿ Accessibility review checklist

This is a checklist for a future audit, not a report of completed testing.

- [ ] Every form control has a visible, programmatically associated label.
- [ ] Required status is communicated without relying on color alone.
- [ ] Invalid input is announced and actionable.
- [ ] Form and contact cards are navigable by keyboard.
- [ ] Focus indicators are visible.
- [ ] Heading hierarchy is logical.
- [ ] Contrast is checked for all foreground/background pairs.
- [ ] Text can be resized to 200% without loss of content.
- [ ] Screen-reader output is checked with at least one supported reader.
- [ ] Narrow-screen layout is verified at common viewport sizes.
- [ ] Dynamic contact addition is announced appropriately.
